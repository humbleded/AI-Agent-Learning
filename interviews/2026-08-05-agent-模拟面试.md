## 逐题记录

### 1. Agent 与普通单轮 LLM 的区别

- 你的回答要点：Agent 能感知并改变外部环境，自主完成目标；普通模型主要输出文本。
- 结论：通过。
- 反馈：已抓住“围绕目标、感知环境并采取行动”的核心。表达时避免把 Agent 等同于单个模型。
- 标准回答：Agent 不是单个模型，而是由 LLM、状态、工具、控制循环和停止条件组成的系统。它为了完成目标，会根据外部观察选择行动、调用工具，并根据结果继续调整或停止。普通单轮 LLM 聊天程序通常只接收输入并生成文本，不会可靠地执行或验证外部行动。

### 2. Schema 在工具调用中的作用

- 你的回答要点：按工具参数和类型生成 JSON，客户端解析并调用工具。
- 结论：通过。
- 反馈：已讲清模型生成结构化参数、客户端解析并调用工具的主链路。还应强调模型输出不可直接信任。
- 标准回答：Schema 规定工具的名称、参数、必填字段、类型、范围和枚举，使模型按约定生成可解析的调用参数。客户端解析后，仍要校验参数、权限和业务规则，再执行工具；因为格式正确的模型输出也可能不符合业务规则或具有风险。

### 3. ReAct 的天气查询流程

- 你的回答要点：解析请求，调用天气工具，观察结果，继续或结束。
- 结论：通过。
- 反馈：完整覆盖理解问题、调用工具、观察结果和决定结束的循环。术语上应区分工具定义与 Action 参数。
- 标准回答：客户端先把天气工具定义提供给模型。模型理解“北京今天是否带伞”后，生成符合 Schema 的工具调用参数；客户端执行工具，并把天气结果作为 Observation 放回模型上下文。模型根据 Observation 判断是否已能回答；能回答就给结论，不能回答则继续下一轮行动，直到完成或触发停止条件。

### 4. 工具连续超时的停止与保护

- 你的回答要点：最大循环次数、超时、连续失败后将错误结果交给模型整理回复。
- 结论：通过。
- 反馈：最大循环次数、超时和连续失败上限正确。下一次应主动说出退避、预算、日志与诚实降级。
- 标准回答：我会设置单次工具超时、有限重试次数和退避、Agent 最大步数以及调用预算。工具失败应作为结构化 Observation 返回给模型。达到上限后必须停止，不能编造实时天气；应向用户说明暂时无法获取结果并建议稍后重试，同时记录必要日志，便于后续排查。

### 5. Plan-and-Solve 与 ReAct 的选择

- 你的回答要点：前者先拆解大目标，后者适合灵活、依据观察推进的问题；指出局部最优风险。
- 结论：通过。
- 反馈：已指出前者有全局拆解、后者依据观察灵活推进，以及局部最优风险。需避免把 Plan-and-Solve 限定为固定流程或必然更贵。
- 标准回答：Plan-and-Solve 适合多步骤、依赖关系明确、需要协调顺序的任务：先形成计划，再逐步执行，并可根据执行结果重规划。ReAct 更适合工具结果不确定、必须边行动边观察的任务。选择时要比较规划成本和返工成本，而不是认为某种模式总是更省或更贵。

### 6. Reflection 与普通重写的区别

- 你的回答要点：先评审、再依意见修改；评审通过即停止。
- 结论：通过。
- 反馈：已说明按明确评审标准发现问题、再定向修改的价值。需补足防止循环空转的多个停止条件。
- 标准回答：Reflection 是“生成初稿、按明确标准评审、依据可执行反馈修改、再次评审”的闭环；普通重写没有明确评审标准，改进不可验证。评审与修改是两种职责，不一定要两个独立 Agent。除了评审通过，还要用最大迭代次数、连续无可验证改进和预算上限来停止反思循环。

### 7. 自动生成一周学习计划的综合设计

- 你的回答要点：Plan-and-Solve 拆每日目标，ReAct 动态调整，Tool Calling 获取信息，Reflection 优化计划；提出 Sandbox。
- 结论：部分通过。
- 反馈：模式组合合理，但安全边界仍偏抽象；Sandbox 只是其中一项，不能替代权限与确认机制。
- 标准回答：先用 Plan-and-Solve 把一周目标拆成可验证的每日目标；通过只读工具获取学习进度、日历和资料；再用 ReAct 根据每天的实际完成情况与工具结果调整后续安排；最后用 Reflection 对照学习目标、负荷和覆盖范围审查计划。安全上默认工具白名单和只读权限，写文件、创建日历或修改计划前必须取得用户确认；执行前校验参数，限制步骤和预算，并最小化处理私人学习数据。Sandbox 可用于隔离高风险执行，但不能代替这些控制。

## 本次结论

核心概念、控制循环与可靠性回答稳定。综合设计中的安全边界仍偏抽象。
