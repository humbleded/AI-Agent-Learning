## 一、摘要 vs 改写（问答①）

- 判断尺子：**信息量变不变**。
- **摘要 Summarizing = 压信息**：长 → 短，丢次要，信息变少（本质是「有损压缩」）。
- **改写 Transforming = 换外壳**：信息不变，只换形式（语言 / 语气 / 格式 / 纠错）。
- 分类自测：会议纪要 → 5 条待办 = 摘要；中译英 = 改写；JSON → HTML = 改写；长文 → 100 字 = 摘要。

## 二、控制摘要长度（问答②）

三种「单位」都能卡：

| 单位 | prompt 写法 |
| --- | --- |
| 词数 | 「最多 30 个词汇」 |
| 句数 | 「最多 3 句话」 |
| 字符数 | 「最多 30 个字符」 |

- ⚠️ **易错点**：长度是**软约束**——模型「尽量靠近」，不是分毫不差（中文按「字」、英文按「词」算法不同，常会差几个）。要严格卡死，得在**代码里再截一刀**。
- 管「范围」还有两招：**聚焦角度**（如「聚焦价格相关」）、**提取**（见下）。

## 三、概括 vs 提取（同一需求，换个动词效果差很多）

- **概括 summarize**：模型想给你**全貌**，哪怕加「聚焦物流」也可能捎带价格 / 质量。
- **提取 extract**：只挖你点名的那类信息，别的句子一律不要，**更干净、更专一**。
- 选用：要**全貌** → 概括；只要**某个具体维度**（运费 / 价格 / 某功能）→ 提取。
- 比喻：概括 = 让同事「把整篇缩几句」（面面俱到）；提取 = 让同事「只挑关于物流的句子」。

## 四、判断摘要漏没漏重点（问答③，书里没直接给）

- 前提：摘要是有损压缩，一定丢东西；「漏没漏重点」**没有绝对标准，取决于你在乎什么** → 第一步永远是**先定义「什么算重点」**。
- 三种查法：
  1. **人工对照**：自己先凭原文列出关键点，再数摘要覆盖了几个，没覆盖的就是漏的。
  2. **提取反查**：对每个在乎的维度用「提取 XX 信息」各跑一次，和摘要对照看有没有体现（**提取 = 摘要的体检工具**）。
  3. **聚焦重摘**：怀疑某方面被漏，就专门「聚焦那方面」再摘一遍，和原摘要对比。

## 五、改写 / 转换 四类外壳（第 6 章）

| 外壳 | 例子 |
| --- | --- |
| 翻译 | 中 → 英 / 西 |
| 语气 / 风格 | 「小老弟…」口语 → 商务信函 |
| 格式 | JSON → HTML 表格 |
| 纠错 | 修拼写 / 语法 |

- 实用点 1：多个转换能**串在一个 prompt**（翻译 + 改语气 + 输出 JSON）——对应后面 `PR2-Gate 邮件处理器`。
- 实用点 2：纠错可用 `redlines` 库显示「改前 → 改后」修订痕迹（了解即可）。
- 对 PR2-02：理解它是「摘要的对照面」就够（摘要**减信息** / 改写**换外壳**），不深抠每个转换。

## 六、三问答速答（收口）

1. **摘要 vs 改写**：压信息 vs 换外壳。
2. **限长度**：词 / 句 / 字符 三单位（软约束）+ 聚焦角度 + 提取 管范围。
3. **判断漏重点**：先定义重点 → 用提取 / 聚焦重摘 逐项核对。
