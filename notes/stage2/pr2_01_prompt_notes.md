## 1. 零样本 / 单样本 / 少样本提示

- **示例(Exemplar)= 塞给模型看的「做好的样题」**；三者唯一区别 = 给几道样题。
- **zero-shot**：不给样题，直接下命令，靠预训练泛化能力；边界模糊，全凭模型自己推断。
- **one-shot**：给 1 道样题，主要是**教格式 / 输出风格**（照葫芦画瓢）。
- **few-shot**：给多道、且**特意覆盖不同情况**（如负面 + 中性），帮模型摸清**任务的边界和细微差别** → 答得更准。
- 一句话本质：**用「样例示范」代替「文字解释」来教模型**；有时 2 个好样例顶 5 行啰嗦说明。

## 2. 指令调优的影响

- **老 GPT-3 = 「文本补全」机器**：擅长顺着开头续写，但**不一定听直接命令**。
- **指令调优(Instruction Tuning)**= 拿大量「**指令 → 回答**」配对的数据，对预训练模型**再微调**，让它学会「听命令、照做」。
- `ChatGPT` / `DeepSeek` / `Qwen` 全是**指令调优过**的版本 → 所以能**直接下人话命令**（也是第 1 块 zero-shot 能成立的原因）。
- 对比：只会补全的老模型 → 得用 **few-shot 示范**它才会；指令调优的新模型 → 一句命令即可。

## 3. 基础提示技巧：角色扮演 + 上下文示例

- **角色扮演(Role-playing)**：开口先给模型**安一个身份**（「你是资深 Python 专家」）→ 控制**风格 / 语气 / 知识深度**。
- **上下文示例(In-context Example)**：原文「与少样本提示的思想一致」→ **就是 few-shot 的应用**；给「输入 → 输出」样例 → 控制**格式（尤其锁 JSON）/ 特定风格**。
- 一句话：角色扮演管「**怎么说**」，上下文示例管「**长啥样**」。

## 4. 思维链 CoT

- **治什么病**：要算数 / 多步推理的复杂题，直接问答案容易「一步蹦答案、蹦错」。
- **怎么用**：prompt 加一句「**请一步一步思考**」/「Let's think step by step」即可触发。
- **好处**：① 答案**更准**（拆小步，每步不易错）；② 过程**看得见** → 能检查它哪步错、更可信好纠错。
- 对应 DLAI 第二原则「**给模型思考时间**」，别逼它一口气出答案。

## 5. 串起来：今天 3 个必答问题的料

1. **好 prompt 通常包含哪些要素？** → 清晰具体的指令（DLAI 原则1）+ 必要时给 few-shot 示例 + 角色扮演定风格 + 复杂题加 CoT 给思考时间。
2. **few-shot 解决什么？** → 用样例划清任务**边界和细微差别**、锁定**输出格式/风格**；省得用一大段文字解释。
3. **prompt 何时越长反而越差？**（材料没直说，留给练习展开）→ 线索：塞了**无关 / 冗余**示例会**稀释**核心指令、超长上下文里关键信息易被忽略、还更费 token。**长 ≠ 好，相关 + 清晰才好。**
