> 资料：HA 第三章 3.2.1 提示工程 (2)~(5) + DLAI Guidelines / OpenAI Prompt Engineering（补充）
> 今天只读概念 + 记笔记，不写代码。动手写 3 个 prompt 对比排在 L1-Gate 之后。

## 1. 零样本 / 单样本 / 少样本提示

- **示例(Exemplar)= 塞给模型看的「做好的样题」**；三者唯一区别 = 给几道样题。
- **zero-shot**：不给样题，直接下命令，靠预训练泛化能力；边界模糊，全凭模型自己推断。
- **one-shot**：给 1 道样题，主要是**教格式 / 输出风格**（照葫芦画瓢）。
- **few-shot**：给多道、且**特意覆盖不同情况**（如负面 + 中性），帮模型摸清**任务的边界和细微差别**；是否提高准确率要靠实际案例比较，错误或不相关的样例也可能带偏。
- 一句话本质：**用「样例示范」补充或替代部分「文字解释」来引导模型**；有时 2 个好样例顶 5 行啰嗦说明。

## 2. 指令调优的影响

- **老 GPT-3 = 「文本补全」机器**：擅长顺着开头续写，但**不一定听直接命令**。
- **指令调优(Instruction Tuning)**= 拿大量「**指令 → 回答**」配对的数据，对预训练模型**再微调**，让它学会「听命令、照做」。
- 本课使用的是面向对话和指令的模型版本；不能由 `DeepSeek` / `Qwen` 等系列名推断其所有版本都经过相同的指令训练。
- 对比：指令调优通常改善直接按要求完成任务的能力，但不是 zero-shot 存在的前提；原始 GPT-3 也做过 zero-shot 测试。是否需要样例取决于具体模型与任务，不能概括成“老模型不给样例就不会，新模型一句命令就一定会”。

## 3. 基础提示技巧：角色扮演 + 上下文示例

- **角色扮演(Role-playing)**：开口先给模型**安一个身份**（「你是资深 Python 专家」）→ 引导**风格 / 语气 / 解释侧重**；这个身份不会凭空增加真实知识或保证专业判断正确。
- **上下文示例(In-context Example)**：原文「与少样本提示的思想一致」→ 用「输入 → 输出」样例引导**格式 / 特定风格**；给 1 个样例是 one-shot，给多个是 few-shot。样例不能锁死 JSON 格式，仍需对应的输出模式和代码校验。
- 一句话：角色扮演管「**怎么说**」，上下文示例管「**长啥样**」。

## 4. 思维链 CoT

- **治什么病**：要算数 / 多步推理的复杂题，直接问答案容易「一步蹦答案、蹦错」。
- **怎么用**：早期提示方法常加入「**请一步一步思考**」/「Let's think step by step」，引导模型输出解题步骤；这不是保证正确的开关，专门训练过的推理模型也不一定需要这句提示。
- **可能的好处与边界**：分步方法在部分任务上能改善结果，输出的步骤也便于核对算式和依据；但可见解释未必忠实反映模型实际形成答案的原因，不能因为“过程看起来合理”就信任结论，仍要用计算、来源或测试核验。
- 对应 DLAI 第二原则「**给模型思考时间**」，别逼它一口气出答案。

## 5. 串起来：今天 3 个必答问题的料

1. **好 prompt 通常包含哪些要素？** → 清晰具体的指令（DLAI 原则1）+ 必要时给 few-shot 示例 + 需要时指定表达角色；复杂题讲清目标、约束和检查标准，是否增加分步提示要结合模型与实测效果。
2. **few-shot 解决什么？** → 用样例说明任务**边界和细微差别**，引导**输出格式/风格**；不能替代程序对结果的检查。
3. **prompt 何时越长反而越差？**（材料没直说，留给练习展开）→ 线索：塞了**无关 / 冗余**示例会**稀释**核心指令、超长上下文里关键信息易被忽略、还更费 token。**长 ≠ 好，相关 + 清晰才好。**
