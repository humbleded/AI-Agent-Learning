## 已采用的具体场景

主要使用者：新接手 Python 服务的开发人员。

主要任务：查清本地启动所需配置，区分适用版本，并找到文档出处。选“工单服务”作为例子，即记录问题与处理进度的程序；当前不实现这个业务程序。

原查找方式：逐份翻 README、配置说明和交接手册，核对版本及参数。本助手将整理这些资料供后续查询。

未来产品代表性问题：“工单服务 1.0 在本地使用哪个默认端口？依据在什么文档的哪一节？”可靠回答应来自适用版本且可访问的原文，附定位；资料不足时说明不足。回答功能属于 R6-03，当前尚未实现。

这是助手根据工程文档产品方向制定的教学场景，不是某公司的真实工单。服务名称、端口、配置名和样本文字都是教学设定。

## 输入、操作和完成结果

当前从助手自行编写的 `sample_docs/quickstart.md` 入手；后续在对应检查点增加 TXT 配置说明、可提取文本的 PDF 交接手册，以及按许可选择的公开官方文档/项目 README 迁移样本。样本将持续用于导入回归，未到检查点的文件不提前创建。

首个小成果：真实读入一份文件，展示正文与来源信息；保留配置名、代码块、换行和缩进。手工创建 Document 只是讲解用演示，不能代替真实 Loader 读取证据。

完整 R6-01 成果：三种格式通过 Loader 读为统一 Document，携带来源等 metadata；通过 Splitter 切成可定位片段，保留标题、页码/段落、版本、内容摘要、团队、文档和片段编号。重复导入不重复生成；更新后当前数据不混入旧版本；删除后文档、片段和导入状态清理完成，展示未来删除检索向量所需的稳定 document_id/chunk_id 关联。

初始只处理明确给定的教学资料和经过选择的公开文档，不扫描个人目录、知识库、`.env` 或真实公司文件，不连接企业账号。第一组样本属于虚构 `demo-team`；团队归属由可信导入配置给定，不让正文自行覆盖。后续用两组虚构团队样本检查状态隔离；仅保存 tenant 字段不等于已经实现权限系统，认证与检索权限过滤按后续任务实现。

文档中的命令只是数据，导入程序不得执行。解析失败、空页、超长段落、重复文件和编码异常都要有可观察的记录。

## 五个连续学习目标

进入下面目标前先完成必要的 RAG 入门：为什么模型需要外部资料、资料准备与查询生成两阶段、检索结果怎样随问题交给模型，以及 RAG 和训练模型/使用 LangChain 的区别。2026-09-07 用户指出前次教学跳过整体原理，因此先补讲，再接回当前组件；这属于本任务前置，不新增独立课程或重置题量。

| 目标 | 为什么做 | 可见成果 |
| --- | --- | --- |
| 1. 读入正文与来源 | 不同文件转成一致的处理对象，同时保留依据 | 一份真实文件的 Document 与 metadata |
| 2. 扩到 Markdown/TXT/PDF | 格式不同，提取方式和位置表示不同 | 三格式结果及解析/编码异常 |
| 3. 切成可定位片段 | 后续能只找相关内容，保留足够上下文 | 切分展示、大小/重叠/结构取舍、超长内容检查 |
| 4. 管理重复、更新与删除 | 文档变化后，当前内容仍然准确 | 稳定编号、去重、更新/删除和团队状态边界 |
| 5. 展示与核验 | 证明真实行为符合当前标准 | 轻量确定性测试、异常处理和用户解释 |

这五项是任务覆盖目标，不是每日配额，不按字段拆成多套题。通过的即时或操作证据计入任务覆盖；只补新增缺口。测试保护真实导入代码，不建一次性 runner 或平行评估平台。
