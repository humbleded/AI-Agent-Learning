#### A4-04-C3 前置澄清 — 类型别名

- 用户问题：

  > `LLMCall = Callable[[str], str]`
  > `StepResult = tuple[str, str]` 这是什么

- 澄清：
  - 两行都是类型别名，只为一类“数据形状”取容易阅读的名字，不会调用 LLM，也不会自动创建元组。
  - `Callable[[str], str]` 表示“接收一个 `str` 参数、返回一个 `str` 的可调用对象”；在本任务中就是 `prompt: str -> 模型函数 -> response_text: str`。
  - `tuple[str, str]` 表示“长度固定为 2，两个元素都是字符串的元组”；在本任务中约定为 `(step, result)`。
  - `list[StepResult]` 因而表示多个 `(步骤字符串, 结果字符串)` 组成的列表。
  - 类型提示主要服务于阅读、编辑器和静态类型检查；Python 通常不会仅凭这两行在运行时自动阻止错误类型，真实边界仍需代码或测试保证。

#### A4-04-C3 前置澄清 — 为什么要导入 `Callable`

- 用户问题：为什么写 `from collections.abc import Callable`，能否直接写 `Callable`。
- 本地 Python `3.13.13` 最小验证：
  - 未导入直接执行 `LLMCall = Callable[[str], str]`：抛出 `NameError: name 'Callable' is not defined`。

- 概念边界：
  - `Callable` 不是 Python 内置名称，导入相当于把该名称带入当前文件的名字空间。
