# D1 迁移到邮件分类（工作/账单/促销/其他）
答（终版·干净）：
LABELS = ["工作", "账单", "促销", "其他"]
def classify(text):
    if any(word in text for word in ["工作", "项目", "会议"]):
        return "工作"
    elif any(word in text for word in ["账单", "发票", "付款"]):
        return "账单"
    elif any(word in text for word in ["促销", "优惠", "打折"]):
        return "促销"
    else:
        return "其他"
# 第2问：兜底类 = 「其他」，防止不属于前三类的邮件无处可去。
# 第3问：邮件场景分类特征硬（发件人域名、「发票」「优惠」「退订」等词），规则版往往就够、又快又免费。
判定：PARTIAL → RETRY → PASS
中间坑（重点·两个错误理解）：
  ① 初版标签带尾随空格 'account '/'账单 '/'促销 '/'其他 ' —— 自己定义标签时手抖带空格，下游 if label == "账单" 因 "账单 " != "账单" 匹配失败（比模型返回带空格更隐蔽，自己跑不报错、接下游才炸）。标签首尾永远别留空格。
  ② 订正时把 strip 误当「万能去空格咒语」到处贴：写出 ['工作',...].strip() 和 [...].strip() —— list 没有 strip 方法，会直接 AttributeError 崩；还给自己手写的干净字面量 "工作".strip() 贴 strip（多余）。
  正解：strip() 是【字符串】方法、只洗【运行时拿到、你控制不了的脏数据】（模型输出 "投诉\n" / 用户输入 / 文件内容）；自己写的常量打错了就改字面量本身，一个 strip 都不该有。最终干净版零 strip。
延伸追问：word.strip() in text 语法可以（word 是字符串、不崩），但对手写干净列表多余；只有关键词从文件/输入等脏源读进来时才该 strip。

def route(text):
