## A4-04-F1 — 模型调用异常后的级联故障

### 原始作答

> 1.在第一次调用模型生成计划，然后调用execute_plan把计划和当前步骤取出并给模型的时候，会把None字符串带给模型，导致模型这一步可能不知道怎么处理，返回的也是None，解析的时候，None没有strip()，导致报错
> 2.必须维持是列表且每个元素是不为空的字符串，可能返回的是字符串的None
> 3.        if result is None:
>             raise ValueError(f"步骤 '{step}' 返回了 None，违反了预期边界条件")
>         if any(r is None for _, r in history):
>             raise ValueError(f"历史结果中存在 None，违反了预期边界条件")

### 批改

- 做对：
  - 找到了实际 `None` 进入执行结果和历史后，最终在 `.strip()` 处触发异常这一主传播方向。
  - 意识到应在结果进入 `history` 前设置运行时边界检查；`raise ValueError` 可作为 fail-fast 策略的一部分。
- 需要订正：
  1. 故障注入返回的是 Python 值 `None`，不是字符串 `"None"`；字符串 `"None"` 仍是 `str`，调用 `.strip()` 不会触发本次 `AttributeError`。
  2. 第 3 步的假适配器实际返回 `"r3"`，不是再次返回 `None`。不可靠之处是第 3 步 prompt 已携带 `('s2', None)`，而不是它必然让模型继续返回 `None`。
  3. `LLMCall = Callable[[str], str]` 约束的是“接收 prompt 字符串、返回响应字符串”的可调用对象；`list[str]` 是 `parse_plan` 的返回类型，`StepResult` 才是 `tuple[str, str]`。
  4. 只让 `build_recap` 的 `.strip()` 接受 `None`，不能撤销已经发生的状态污染：`None` 已进入 `results/history`，并被带进第 3 步 prompt。
  5. 所写两段是生产代码中的检查，不是题目要求的回归测试；缺少假适配器输入、调用动作以及 `assert`。
  6. 若选择遇到 `None` 立即抛出 `ValueError`，完整流程的预期就是“受控提前失败”；要同时满足“完整三步不崩”，还需由外层捕获并转成满足契约的执行结果，或在写入 history 前采用一致的降级策略。
