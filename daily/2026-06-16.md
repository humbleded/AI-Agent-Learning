答（PARTIAL → 复测 PASS）：

# 1. 存=json.dump(写入文件)，读=json.load(读回)。方向对，但原答把 load 说成“做存”——
#    存是 dump、读才是 load。（带 s 的 dumps/loads 对字符串；存盘/读盘用不带 s 的 dump/load 配文件对象，已选对。）
# 2. 对得上：list→JSON数组→读回还是 list，dict→JSON对象→读回还是 dict，

# tuple 的坑（订正）：不是“不可变→无法添加历史”——history 是外层 list，append 照样能加；
#    tuple 不可变只是不能改某条消息内部。真正的坑是 JSON 没有 tuple 类型：

D2. （迁移 / 对比）如果只想让助手“永远记得用户叫三玖”，不靠多轮历史，能不能用 `SYSTEM` 那条消息实现？怎么做？这跟“多轮记忆”在本质上有什么不同？

答（PARTIAL → 复测 PASS）：

```python
# 能用 system 实现：{"role":"system","content":"用户叫三玖"}。✓ 高层直觉也对。
# 关键订正：“system 只在初始发送、后续不发”是错的，跟“接口无状态”冲突。
#   服务端两次请求之间什么都不记，所以 SYSTEM 每一轮都要重发——
#   见 l1_03_chat.py:65 messages=[SYSTEM]+history+[本轮user] 在 while 里每轮都执行。
# 为什么 system 里的名字“永远记得”？不是发一次就够，而是 SYSTEM 是代码里写死的固定常量，

```
