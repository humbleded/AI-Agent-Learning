```python
# A2 控摘要长度的三单位 + 为什么软约束
答：字、词、句（「不超过 30 个字 / 30 个词 / 3 句话」）。软约束：因为模型输出的是 token，字/词/句不能与 token 一一对应，且模型边写边凑、没有精确计数器，凭感觉写。
判定：PASS
补：更根本一层——模型无计数器、凭语感估着写（天生做不到分毫不差）；token≠字/词是叠加的一层。实用结论：要严格卡死得在代码里再 len() 截一刀。
```

```python
# A3 概括 vs 提取 区别 + 场景
答：概括尽可能压缩并保留更多信息、从全局出发；提取只关心点名那部分、其余忽略。概括适合演讲/总结全貌，提取适合找某条具体信息。
判定：PASS
钉死：概括求「全」，提取求「专」；「专」正是提取更干净的原因（B3 深挖）。

# B2 为什么先定义「什么算重点」+ 有无绝对标准
答：模型没有「重点」概念，重点是人为/主观定义的，所以先定义；直接看摘要可能漏掉你想要的信息。查法：人为先列重点→与摘要对照看是否覆盖；或让模型提取人为重点再与摘要对比。
判定：PASS
钉死：摘要是有损压缩、一定丢东西，「漏」不可避免，真正的问题是「丢的是不是你在乎的」；在乎什么取决于目的（给老板看=结论，给法务看=风险），换用途重点就变 → 无绝对标准。体检三件套：① 人工对照 ② 提取反查（提取=摘要体检工具）③ 聚焦重摘（你没提的第三招）。
```

```python
# B3 总结·聚焦 vs 提取 差在哪
答：总结从全局出发，重点保物流时仍尽量带上其他信息；提取只关心物流一个方面，其余忽略。
判定：PASS
钉死：两个动词「默认任务目标」不同——总结默认「给全貌」（聚焦只调侧重、不改本性，压不住捎带）；提取默认「做过滤」（只留点名、扔掉其余）。要某具体维度且要干净 → 用提取，别用「聚焦总结」。
```

```python
# B4（复习 PR2-01）few-shot 真实示例 vs schema/格式说明
答：「评论：这吹风机… -> {"summary":"…","points":[…]}」是真实示例；「只输出 JSON，字段为 {"summary":"...","points":["...","..."]}」是输出格式（schema）。两者不是一回事，维度不同。
判定：PASS ✅（PR2-01 反复踩的坑，这次一次答对，弱点填上）
钉死：schema=说明书（抽象描述格式、带占位符，属清晰指令）；few-shot=样板（真实输入→真实输出，属上下文示例）。两个不同技巧，可只给 schema、只给示例、或都给（本题都给了→锁得最稳，延续 PR2-01 C2）。
```
