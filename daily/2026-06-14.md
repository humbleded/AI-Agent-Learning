1. 你的数据结构为什么这样设计？
   数据结构设计为列表嵌套字典，每条学习记录包含日期、主题、分钟数和笔记，便于按时间顺序存储和检索学习记录。

4. 这个脚本后续如何变成学习追踪系统的一部分？
   脚本通过记录每日学习日志，并支持查看最近的学习记录，可以作为学习追踪系统的基础模块，后续可以扩展为统计学习时长、生成学习报告等功能。

L1-01：

1. API Key 是身份、权限、还是模型本身？
   API Key 是身份和权限的凭证，用于验证调用者的身份并授权访问特定的模型和服务，而不是模型本身。
2. 对比 DeepSeek 文档里 curl（原生 HTTP）和 Python SDK 两种调用方式，SDK 帮你省掉了哪些步骤？
   SDK 帮你省掉了拼接 URL、加 `Authorization: Bearer <key>` 鉴权头、`Content-Type: application/json`、

3. 为什么要把模型名作为参数传入？
   因为不同的模型有不同的能力和适用场景，通过传入模型名可以指定调用哪个模型，从而获得期望的输出结果。

Codex 对问题/不确定点的解释：

- `P0-Gate` 的数据结构可以理解成“一个账本”：整个 JSON 是账本列表，每条记录是一个字典，里面放 `date`、`topic`、`minutes`、`note`。这样适合追加新记录，也方便用 `logs[-7:]` 取最近 7 条。
- 文件不存在时返回空列表，是合理的第一版策略。意思是“还没有账本，那就从空账本开始”，比直接报错更适合学习记录 CLI。
- SDK 和 curl 的关系可以这样理解：curl 是你亲手写信封、地址、邮票和内容；SDK 是快递柜台，它帮你封装 URL、鉴权头、JSON 序列化、POST 请求和响应对象解析。但底层依然是在发 HTTP 请求。
- API Key 不是模型本身，而是“门禁卡”：它证明你是谁、有没有权限调用服务。模型名才决定你要进哪个“房间”，比如不同模型的能力、速度、价格可能不同。
- 当前 PowerShell 环境里有 `DEEPSEEK_API_KEY`，所以脚本能跑通；但 `.env` 文件里目前只看到 `TEST_VARIABLE`。如果换一个终端后运行失败，很可能是那个终端没有这个环境变量。
