```python
# A2 trim_history 的 -MAX_TURNS*2 里 *2 的含义
答：*2 表示切偶数条，保证一轮完整对话；直接 history[-MAX_TURNS:] 可能有答无问。
判定：PASS
点睛：核心是「1 轮 = 2 条消息（user+assistant）」，所以保 N 轮要 ×2；history[-MAX_TURNS:] 单位是「条」不是「轮」，会从某轮中间切断。
```

```python
# A3 要可复现 temperature 设多少 + 怎么挑词
答：设成 0；模型会扩大概率差距，低概率压到几乎 0、高概率进一步加大。
判定：PASS
点睛：temperature=0 是「扩大差距」的极端 = 每步只挑概率最高那个词（贪心/argmax 解码），无随机、可复现。
```

```python
# B1 call_model vs call_messages，为何非流式必用后者
答：call_messages 把 [system]+历史+question 一起发；call_model 只发本次问题，相当于让模型没记住历史。
判定：PASS
```

```python
# B2 timeout 为何不在 DeepSeek API 文档 + 属哪层 + 同层再举一例
答：timeout 不是模型功能，是发请求时给 SDK 的功能；属网络/客户端层，不是模型参数；同层再举：max_retries。
判定：PASS（订正后）
中间坑：③ 先想到 apikey，订正为 max_retries（SDK 自动重试次数）。判断法：会发给服务器、影响生成的 → API 参数；只在本机管怎么发/等多久/重试几次 → SDK 参数。
```

```python
# B3 return None vs 友好字符串对 history 的影响
答：print(f"助手：{answer}") 会打印 None，用户不懂；history.append content=None 会把 None 带入毒化模型。
判定：PASS
补充：下一轮 build_prompt 把 content=None 发出去，API 要求 content 是字符串 → 很可能下一轮直接报错，一个 None 滚雪球带崩后面。返回友好字符串两头都解。
```

```python
# B4 普通请求-响应 vs SSE 流式，形态差异
答：① 方式一一次性返回、要等模型全部答完；② 方式二边生成边推、靠 for 循环一点点拼；③ 体感方式一白屏久等、方式二打字机逐字，总时间其实差不多、流式甚至略有开销。
判定：PASS（答得很完整）
点睛：流式赢在「首字时间 TTFT」短——总时长接近，但第一个字很快出，不用对白屏干等。
```

对问题/不确定点的解释：

- `timeout`/`max_retries` 是 SDK 客户端参数、不进请求体，所以 DeepSeek API 文档查不到；OpenAI SDK 的 `create()` 签名里有 `timeout: float | httpx.Timeout | None`。
- SSE（Server-Sent Events）：服务器把一条 HTTP 连接攥住不挂、单向逐块推文本，模型「逐字蹦」就是靠它；SDK 把每块解析成 chunk 喂给 `for chunk`。
- 错误兜底返回友好字符串（非 None）：既给用户可读提示，又让 history 始终是合法字符串，避免下一轮把 content=None 发出去导致 API 报错的雪崩。
