#### R4b 概念追问｜`is not True` 与普通真假判断

- `if value` / `if not value` 会调用 Python 的真值规则；1、非空字符串、非空容器都属于 truthy。
- `value is True` / `value is not True` 检查对象身份；只有真正的布尔单例 True 通过严格成功合同。
- `value != True` 也不适合严格校验，因为 Python 中 `1 == True` 为 True；本边界使用 identity 是有意的协议类型校验，不是普通业务分支的风格偏好。

#### C3c 协议追问｜为什么不能把 tool_calls 直接当 Tool Message

> `tool_result_message = {"role": "tool", "tool_call_id": tool_call_id, "content": json.dumps(tool_result, ensure_ascii=False)}` 为什么不直接用 tool_calls，而是要构建一个

教学说明：`assistant_message.tool_calls` 是模型发出的调用请求，包含调用 ID、工具名与模型生成的参数，但不含客户端真实执行结果；该完整 assistant message 已作为第三条消息回传。客户端按请求执行后才得到 `tool_result`，必须新建 `role="tool"` 消息，把结果序列化到字符串 content，并用 `tool_call_id` 指明它回复哪一个请求。直接再次放入 tool_calls 只是在重复“请调用工具”，不能形成 Observation。若有多个 tool_calls，客户端应为每个调用分别执行并生成一条对应 ID 的 tool message；本检查点合同只接受恰好一个。
