### `W5-ALG-R1-F1`｜两数配对，思路环节

题面：给定整数列表 `nums` 和目标整数 `target`，寻找两个不同位置的数字，使它们的和等于 `target`。有解时返回两个下标 `[i, j]`，要求 `i < j`；无解返回 `[]`。输入可以为空，也可以包含负数、零或重复值；有解时保证恰好一对有效下标；不得修改输入列表。

示例：`nums = [8, 3, 12, 6]`，`target = 14`，应返回 `[0, 3]`，因为这两个位置对应的数是 8 和 6。示例只说明输入输出，不给出算法过程。

本轮待作答问题：先用文字设计一个借助 Python 字典记录信息的方案。说明字典中的一条记录代表什么；处理当前数字时怎样判断能否配对、何时更新记录；为什么这个流程不会重复使用同一个位置。当前只答思路，代码、真实测试与复杂度解释留在同题后续环节。

独立性边界：题面给定使用字典，因此不能把「选择字典」计为用户独立证据；未展示补数公式、具体键值安排、正确更新顺序或参考实现。用户应暂不查看旧代码、历史答案和查漏资料；本轮是否需要提示据实际回答记录。

原始作答：

> 1. **字典记录什么信息**
>    字典中每一条记录保存：
>    - 键：已经扫描过的某个数字值；
>    - 值：这个数字在原列表中的下标。
>      更具体地说，保存的是“当前数字之前”已经出现过的数字及其位置，比如记录成：`数值 -> 下标`。
> 2. **处理当前数字时怎么判断，何时更新字典**
>    从前往后遍历列表，假设当前位置是 `i`，当前数字是 `nums[i]`。
>    先计算它需要的配对数字：
>    `需要的数 = target - nums[i]`
>    然后去字典里查这个“需要的数”是否已经存在。
>    - 如果存在，说明前面已经有一个位置 `j` 的数字可以和当前数字相加等于 `target`，直接返回 `[j, i]`，因为 `j` 一定比 `i` 小。
>    - 如果不存在，说明当前数字暂时不能和前面任何数字配对，就把 `nums[i] -> i` 写入字典，供后面的数字继续查找。
>    关键是：**先查找，后更新字典**。
> 3. **为什么不会把同一个位置使用两次**
>    因为处理当前位置 `i` 时，字典里只保存了在下标 `i` 之前出现过的数字。当前数字 `nums[i]` 自己还没有被写进字典。
>    所以即使当前数字的值和“需要的数”相同，字典里找到的也是前面另一个相同值的位置，而不是当前位置自己。
>    这样每个位置最多只会作为“历史数字”使用一次，也只会作为“当前数字”处理一次，不会重复使用同一个下标。
>
> 如果整个列表遍历完都没有找到配对，就返回空列表 `[]`。

批改与措辞校准：保存对象、补数公式、两个分支、查询/更新顺序、`j < i` 与无解返回均正确；本轮未提供额外提示或参考实现。末句“每个位置最多只会作为历史数字使用一次”概括过满：一个历史记录可以留在字典中，供后续多轮查找使用；决定性保证是命中时历史下标 `j < i`，因此最终返回两个不同位置。前文已独立说明这一原因，只校准措辞，不要求重复作答，也不把它新增为第三个弱点。

def two_sum(nums: list[int], target: int) -> list[int]:
    seen = {}  # 保存已经扫描过的数字及其下标
    for i, num in enumerate(nums):
        need = target - num
        if need in seen:
            return [seen[need], i]
        seen[num] = i
    return []

### 同题 `W5-ALG-R1-F1`｜复杂度解释

题面依据：当前 `two_sum()` 实现及已通过代码，令 `n = len(nums)`。请说明平均时间复杂度和额外空间复杂度，并给出原因：循环最多处理多少个元素；每轮的字典查询/写入按什么平均复杂度计算、依据是什么；字典 `seen` 最多保存多少条记录；据此得出整段函数的时间/空间结论。本轮不给复杂度答案或推导示例，不重问已经通过的保存/查询顺序与同下标防复用。

原始作答：

> 函数的时间复杂度为 **O(n)**，额外空间复杂度为 **O(n)**。
>
> 时间方面
>
> - 循环最多会处理 **n** 个元素，也就是 `nums` 中的每一个元素。
>   如果一直没有找到配对，`for` 循环会从第 0 个元素一直遍历到第 n-1 个元素；如果中途找到配对，会提前 `return`，所以最多是 n 次迭代。
> - 每一轮循环中，主要操作是：
>   - 计算 `need = target - num`：常数时间 O(1)；
>   - 字典查找 `need in seen`：Python 字典基于哈希表，平均查找成本是 O(1)；
>   - 字典写入 `seen[num] = i`：平均插入成本也是 O(1)。
>   因此每一轮的平均操作成本都是常数级 O(1)。
> - 合起来：最多 n 轮，每轮 O(1)，所以平均时间复杂度为 **O(n)**。
>
> 空间方面
>
> - `seen` 字典用来保存已经扫描过的数字及其下标。
>   在最坏情况下，也就是整个列表遍历完仍然没有找到配对时，`seen` 会保存列表中的全部 **n** 个元素。
> - 即使中途找到配对，`seen` 保存的记录数也不会超过已遍历的元素个数，因此上界仍然是 n。
> - 所以额外空间复杂度为 **O(n)**。

批改与精度校准：按本题常规整数/平均哈希操作口径，最多 n 轮、每轮常数次平均 O(1) 操作、最多 n 项额外容器的因果均正确。空间说法应收紧为「最多保存 n 个不同数值的记录」：无解不保证一定有 n 个键，重复值会覆盖既有记录；数字全不同且无解时可达到 n 个键。用户已明确上界，结论不受影响，无需重答。命中分支中的 `seen[need]` 也是常数次平均查询，不改变结论。

复杂度环节结果：`PASS`。
