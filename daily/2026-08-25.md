学习者澄清问题：

> 需要额外配置 **checkpointer 和 thread state**  是什么

澄清与术语校准：前一轮“配置 checkpointer 和 thread state”的说法不够精确。实际关系是：① `checkpointer` 是在 Graph 执行过程中保存和读取 State 快照的组件；② `checkpoint` 是某个执行阶段保存下来的一份快照；③ `thread` 是用 `thread_id` 标识的一条独立业务流程，例如一个故障单；④ `thread state` 不是通常需要另行配置的第二个组件，而是该 `thread_id` 下被保存的当前及历史 Graph State。Graph 编译时接入 checkpointer，调用时提供 `thread_id`，checkpointer 才能把快照归入正确流程并在后续读取。`InMemorySaver` 只保存在当前进程内，进程重启会丢失；要验证重启后恢复，需要 SQLite/Postgres 等持久化实现，这属于 G8-01/02，不在 G8-00 实作。

边界关系：State schema 规定运行数据长什么样；checkpointer 负责存取；`thread_id` 负责区分“这是哪一条业务流程”；thread state 是该流程已经保存的状态。跨 thread 的用户偏好、共享事实等长期资料属于 store / 业务存储，不由 thread state 冒充。

>
> C.本次运行结束后，再次调用 Graph，不会仅仅因为使用了 `StateGraph(IncidentState)`，就自动带上 `"timeout log"`。状态会初始化，因为没有长期保存。如果以后希望跨运行续接，需要增加长期记忆功能
