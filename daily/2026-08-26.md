### Edge 片段｜固定流转、条件路由与显式终止

本片段覆盖：

- 普通边 `add_edge(A, B)` 表示 A 完成后固定执行 B；`add_edge(START, first_node)` 指定入口，`add_edge(final_node, END)` 指定终止。
- 条件边 `add_conditional_edges(source, route_fn)` 会在 source 完成后，把最新 State 交给 `route_fn`，由它返回一个有限的下一节点名。
- 当前故障诊断设计中，业务 Node 负责理解日志、调用工具或写入 `evidence_status` / `tool_failed` / `stop_reason` 等结构化字段；路由函数只做确定性判断，不把停止权交给 LLM。
- 同一源节点配置多条普通出边表示并行执行多个目标，并不表示“从中选一个”；互斥分支必须使用条件边。
- 当前设计中，同一来源 Node 也不同时配置普通出边和条件出边，否则固定路径与条件选出的路径都可能执行，造成已经满足停止条件却仍继续诊断。
- 在本片段采用的 `add_conditional_edges` 写法中，路由函数只选目的地。需要写入 `stop_reason` 时，应由前一个业务 Node 或专门的停止 Node 写入，再通过普通边进入 `END`。
