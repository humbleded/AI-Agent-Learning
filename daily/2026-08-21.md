### `A4-Gate-C4b-2b-2a-G1`｜SDK retry 与 Agent retry 的唯一所有权

当前在做什么：在写任何恢复代码前，先冻结“谁有权发起第二次真实 HTTP 请求”。当前 `.create()` 表面上只占一个 Agent step、只写一条七字段日志，但 SDK 默认 `max_retries=2`，所以一次调用可能在内部产生最多 3 次物理 HTTP 尝试。

为什么需要：`max_steps=6`、恢复次数、成本、延迟和日志都以可观察调用为边界。若 SDK 隐藏两次重试，Agent 看到的“一步 / 一条日志”与 Provider 实际收到的“三次请求”不一致；随后再加一次 Agent recovery，还可能把一次逻辑失败放大成最多 6 次物理尝试。

与前后步骤及最终产物的关系：G1 只冻结重试所有权与证据口径。通过后才设计共享异常分类、Candidate 恢复预算并创建一个 TODO 骨架；timeout 数值和具体错误白名单仍在后续实现检查点用真实代码固定。fake client 只能证明 Agent 分支与计数，生产 client 配置仍必须由真实构造器探针 / smoke 单独证明。
