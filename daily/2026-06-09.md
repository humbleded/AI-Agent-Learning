Codex 问答点评与补充：

整体评价：问答能覆盖 P0-05 的核心：为什么拆函数、`return` 和 `print` 的区别、函数职责边界。可以通过。

1. 为什么要把代码封装成函数？
   原答案：让结构更加清晰，复用性更强，方便测试。
   点评：正确。可以再补一句：函数把“输入 -> 处理 -> 输出”固定下来，调用者不用关心内部细节。
   强化版：把代码封装成函数，是为了让一段逻辑可以被命名、复用和测试。函数通过参数接收输入，在内部处理，再用 `return` 输出结果，这样主程序、测试代码或其他模块都可以调用它。

2. `return` 和 `print` 有什么区别？
   原答案：`return` 是函数的返回结果，且函数执行完毕后会返回到调用处继续执行；`print` 只是输出结果到控制台，函数执行完毕后不会返回任何值。
   点评：方向正确，但最后一句要更精确：`print()` 本身也会返回 `None`，不是“函数执行完毕后不会返回到调用处”。普通函数执行完也会回到调用处；关键区别是 `return` 把值交给调用者，`print` 只是显示给人看。
   强化版：`return` 会结束当前函数，并把一个值交给调用者，调用者可以保存、比较或继续使用这个值；`print()` 只是把内容显示到控制台，适合给人看，不能直接作为业务结果继续传递。

3. 如何判断一个函数是否职责过多？
   原答案：如果一个函数的代码行数过多，或者它同时处理了多个不同的任务，就可能职责过多。可以通过检查函数是否可以被分解成更小的函数来判断。
   点评：正确。更实用的判断是：函数名能不能用一句话准确描述它做什么；如果函数名里总想写“并且”，通常说明职责太多。
   强化版：如果一个函数同时负责输入、计算、保存、打印、异常处理等多件事，或者很难给它起一个准确的名字，就可能职责过多。可以把核心计算逻辑拆出来，让它只接收参数并返回结果，交互和打印留给 `main()`。

```python
def make_plan(goal, days):
    if days <= 0:
        return []

    plan = []
    for day in range(1, days + 1):
        plan.append(f"第 {day} 天：围绕 {goal} 完成一个小练习")
    return plan


def score_answer(answer):
    text = answer.strip()
    if not text:
        return 0

    score = min(len(text) * 2, 80)
    for keyword in ["因为", "所以", "例如", "区别", "返回"]:
        if keyword in text:
            score += 4
    return min(score, 100)
```
