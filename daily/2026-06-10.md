Codex 对问题/不确定点的解释：

1. `.venv` 是项目自己的 Python 环境，用来隔离依赖，避免不同项目互相污染。
2. `pip install` 安装到“当前正在使用的 Python 环境”的 `site-packages`，所以激活 `.venv` 后安装的位置就是 `.venv\Lib\site-packages`。
3. API Key、密码、token 这类敏感配置不要写死在 `.py` 文件里。当前阶段用 `.env` + `python-dotenv` 练习读取配置即可，真实 API 调用到 P0-09 和 L1 再深入。

Codex 问答点评与补充：

整体评价：你的三个答案方向都正确，已经达到 P0-06 通过标准。

1. “为什么项目要用虚拟环境？”

原答案能说出“防止不同项目之间的依赖冲突”。更完整的说法是：虚拟环境让每个项目有自己的 Python 解释器入口和第三方包目录，这样项目 A 需要旧版本包、项目 B 需要新版本包时，不会互相影响，也方便复现部署环境。

2. “`pip install` 安装到哪里？”

原答案正确。要再记牢一点：`pip` 跟着当前 Python 环境走。想确认安装位置，可以运行 `python -m pip show 包名`，看 `Location` 字段。

3. “为什么 API Key 不应该写死在代码里？”

原答案正确。补充一点：`.env` 也不应该保存真实生产密钥后随便同步或公开；真正项目里通常会把 `.env` 加进 `.gitignore`，并只提交 `.env.example` 这种示例文件。
