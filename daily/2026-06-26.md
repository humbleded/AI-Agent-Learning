```python
# A1 接口有无状态 + 多轮记忆靠哪端
答：无状态，服务端不存上一轮历史，需要这次把历史一起拼进去发；多轮主要靠客户端把 system+历史+本次问题拼起来一起发。
```

```python
# A2 trim_history 的 -MAX_TURNS*2 为何×2、为何偶数
答（终版）：一轮完整问答 append 2 条（user+assistant），所以保 N 轮要 ×2；偶数是结果不是目的。奇数切片会留下孤立 assistant（有答没问）。
判定：RETRY → PASS
中间坑：第一版因果倒置——说「乘2是为了保证偶数」；订正为「1轮=2条 → ×2，偶数是 *2 的结果」。另：奇数残缺开头是孤立 assistant（有答没问），不是有问没答（trim 跑在两次 append 之后，history 永远偶数、以 assistant 结尾）。
```

```python
# A3 history 每个元素的格式
```

```python
# A4 哪个参数最影响输出稳定性
答：温度 temperature；调 0 稳定可复现（低概率词被压到接近 0），调高更发散多样。
判定：PASS
钉死：本质是温度把词与词的概率差距「压平 or 拉大」——低温拉大差距、几乎只选最高分（可复现）；高温压平、冷门词也有机会（发散）。
```

```python
# B1 call_model vs call_messages，为何多轮必用后者
答：服务端无状态、不记上一轮，需要把历史拼上一起发；用写法一（call_model 只收本轮 question 字符串）模型看不到历史、会忘记之前的对话。
判定：PASS
```

```python
# B2 两个兜底各防什么 + 能否互换
答（终版经纠）：① `delta.content or ""` 防 None——两个后果：`answer += None` 抛 TypeError（崩）、`print(None)` 不崩但屏幕打印出字面 "None"（脏）。② `except` 里 `return f"...失败"` 友好字符串——给用户看 + 避免返回 None 毒化 history。不能互换：①必须 ""（无害占位），②必须友好串。
判定：RETRY → PASS
中间坑：**三次误以为「print(None) 也报错」**。实际 print 任何值都不崩、只把它转成字符串 "None" 显示；会崩的是 `str + None` 这种类型拼接。`or ""` 一招同解「一崩一脏」。
```

```python
# C1 debug：main 循环两个历史管理 bug
答：① `trim_history` 切得太早（放在 append 之前），应移到两个 append 之后；② `history.append(messages)` 错——messages 是整个列表，应 append {"role":"user","content":question}。
判定：PASS（① 后果已纠正）
中间坑：① 我最初把后果说成「奇数/有答没问」——套错了 A2 的概念。① 真正后果是「先砍后存 → 砍的是没算上本轮的旧 history → 每轮实际发出去的历史比 MAX_TURNS 多一轮，限长滞后/形同失效」。修法：trim 放循环末尾，先存后砍。
```

```python
# C2 predict：漏 or "" 的流式循环，content 依次 [None,"你","好",None,"呀"]
答：跑不完，卡在第一个 chunk（content=None），`answer += None` 抛 TypeError；屏幕显示 TypeError。
判定：PASS
补充：crash 发生在 `answer += c` 这行（在 `print(c)` 之前），所以这一轮还没轮到 print 就崩了——屏幕一个字都没印（连"你好"都没出来），直接糊 traceback。印证「开头一个 None chunk 就能让整段输出胎死腹中」，所以 `or ""` 必须有。
```
