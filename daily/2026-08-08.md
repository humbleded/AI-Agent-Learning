### `A4-Gate-C2b`｜`search_web` 工具适配

当前唯一前置决策：确定 V1 搜索后端范围。候选默认是无需新增密钥的 MediaWiki/Wikipedia Search API；优点是可以立即真实调用、返回稳定 JSON，缺点是检索范围仅限 Wikipedia，不能代表整个公开网页。选择会改变 Agent 能找到哪些来源，因此必须由用户确认，助手不代替决定。

用户澄清问题：`search_web是调用模型吗`

教学说明：`search_web` 本身不是模型调用，而是客户端中的普通 Python 工具函数；它通过 HTTP 调用选定的真实搜索服务。完整链路是“客户端调用 DeepSeek → DeepSeek 只生成 `search_web` 的工具名与查询参数 → 客户端校验并执行 `search_web` → 搜索服务返回真实结果 → 客户端把 Observation 交回 DeepSeek → DeepSeek 依据结果生成并反思摘要”。因此选择 Wikipedia 或通用搜索服务改变的是工具的数据来源，不改变本项目仍使用真实 DeepSeek 负责 Agent 推理。

用户行为决策：选择 Wikipedia。V1 据此固定为中文 Wikipedia 的 MediaWiki Search API；不冒充全网搜索，不自动切换语言，后续只有真实需求与评估证据支持时才扩展。

官方与真实调用校准：项目 `.venv` 已安装 `requests 2.34.2`。固定端点为 `https://zh.wikipedia.org/w/api.php`；中文“人工智能”查询在描述性 User-Agent 下返回 HTTP 200、3 条真实结果，首条 `pageid=317`、标题“人工智能”。缺少合格 User-Agent 的首次探针收到 HTTP 403，印证该请求头是实际接口约束而非装饰字段。官方 `list=search` 的 `snippet` 含高亮标签，因此适配层需转换成纯文本；页面 URL 使用稳定 `pageid` 构造 `curid` 地址。

### `W4-ALG-F4-G1`｜独立思路与边界

- 问题：先不要写代码。请用自己的话说明一个满足平均 `O(n)` 的方案：从左到右读到每个元素时，你准备在辅助容器里保存什么；遇到重复值时怎样判断是否返回 `True`；如果当前这次重复距离太远，为什么后续仍可能出现更近的一对、你的方案如何保留这个机会？最后说明 `k=0` 时为什么应始终返回 `False`。
- 用户原始作答：

  > 1.保存元素和元素下标<br>
  > 2.下标不一样<br>
  > 3.循环完后计算距离<br>

- 首次批改：`PARTIAL`。能识别辅助容器需要保存“元素 → 下标”，并正确解释 `k=0` 时不同下标的距离不可能小于等于 0；但遇到重复值时只说“下标不一样”，未检查题目的核心条件 `当前下标 - 历史下标 <= k`。把距离计算推迟到循环结束也没有说明如何维持平均 `O(n)`，且若始终保留第一次出现的旧下标，会漏掉后续更近的有效重复对。
- 当前定向追问：用 `[1, 2, 1, 1]`、`k=1` 追踪下标，修正“保存哪个历史下标、何时比较和更新”；暂不写代码。
- 用户订正：

  > 1.读到下标 2 的 1 时，比较的是下标0的1，因为abs(i - j)结果为2，所以暂时不返回True。<br>
  > 2.应该更新为2<br>
  > 3.读到下标 3 的 1 时，再比较2跟3两个下标，abs(i - j)结果为1,返回True<br>
  > 4.这样距离最近

- 订正结果：能逐步追踪 `0 → 2 → 3` 三次出现，先判断 `2 - 0 > 1`，再把值 `1` 的记录更新为最近下标 `2`，最终由 `3 - 2 <= 1` 命中；已修正“循环结束再比较”的原思路。保存最近下标能为同一数值提供当前最小的历史距离，并保持每步只做常数次哈希查询/更新。

  def contains_nearby_duplicate(nums: list[int], k: int) -> bool:
      """判断 nums 中是否存在下标距离不超过 k 的相同数值。"""

### `W4-ALG-F4-G3`｜复杂度与正确性解释
