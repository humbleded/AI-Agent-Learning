# 每日学习计划

配合 `weekly-plan.md` 使用。**核心：先用 `weekly-plan.md` 定位当前内容块，再用 `tracker/progress.md` 找该块里下一个应推进的任务；不要机械取全表第一条 TODO，B0、算法与 Gate 填充项按触发规则穿插。** 哪天做、做几个，看当天状态；有事耽误提前跟我说，那天顺延、任务吸收到后面，连续性优先。

不再按周一到周日把强度排死（废弃「周一周五特别轻」「满血 / 半血 / 空血」这类按具体星期定档），**但保留「工作日小块推进 / 周末整块攻关」的任务类型分工**——见下「二、固定规则」。

**计划硬上限：默认每天最多 180 分钟，可以完整排满，不强制预留 15–20 分钟缓冲。** 只统计用户主动参与的阅读/带读、即时考察、正式练习、编码/操作、算法，以及明确共写或复核 notes；不记录实际学习时长。助手读取资料、处理卡顿、等待工具/网络/测试、自动整理与写回不占计划预算，常规订正也不另列时间槽；若订正/debug 扩展成补救单元，就优先完成补救并顺延剩余范围，任务保持 `DOING`。

**休息日双块只按显式口令启用**：用户明确说「今天不上班，状态好，按休息日双块安排」或同义口令时，第一块 ≤3 小时，充分休息后第二块 2–3 小时，全天最多两块/6 小时。第二块选独立的 Gate/项目/debug/部署单元、下一学习单元或算法时段，不再增加一套概念题；临时只做一块不记欠账。

## 一、每天的节奏

- **主块**：先用 `weekly-plan.md` 定位当前内容块，再用 `progress.md` 找这个内容块里未完成的任务（概念阅读 / 写代码 / 过 Gate / 项目）；不要机械地取表格第一条 TODO。概念/阅读默认“一个片段带读 → 一道即时考察 → 记录证据”，当天资料过长就拆单元。
- **碎片阅读**：白天可用手机读日计划中的纯阅读项（中文文档 / 笔记 / 视频段落），不写代码、不依赖电脑；它仍计入 180 分钟计划容量，不是额外加餐。没读懂的内容放回整块带读范围。
- **正式练习与收尾**：一个完整概念学习块通常随 4–7 个自然片段产生即时考察，再按任务全部关联 daily 的证据补 3–5 道非重复闭卷题，以任务级 8–12 个总有效考察为覆盖目标与上限，跨日不重置。计划直接给用户作答、必要的共写/复核分配时间；助手自动整理任务要求的 notes、更新 `daily/tracker` 不占预算，也不要求机械预留收尾缓冲。旧复习目标默认 1 个、最多 2 个，计入同一覆盖预算。
- **算法时段**：算法按内容块累计，但只在日计划明确分配的 30–45 分钟独立时段做；它替换当天部分主块，不能追加到已经排满 180 分钟的全天计划之外。
- **普通日计划仍有容量时**：先补齐当前单元的正式证据和用户需要参与的 notes 复核；再推进“能在本块独立收口”的下一学习单元，或执行已经排好的算法时段。不要因助手处理更快就额外扩充定义题量，也不要临时启动会留下半成品的大 Gate/部署；全天计划最多 180 分钟，只有上面的休息日双块口令可以安排第二块。
- 你超前时不必硬塞满；**连续性比单日强度重要**，哪怕只推进一点、写一行打卡，也别断。

## 二、几条固定规则（其余跟着队列走）

1. **Gate / 项目 / 部署 → 周末做**：要整块连续时间。判据是「**能否一坐做完、不留半成品过夜**」——工作日**可**做能起能收的自包含单元（小脚本 / 单函数 / 小实验，如 S-03 的 token 对比），但**不碰**会停在「跑一半、明天得重新捡上下文」的活（Gate 收尾 / 大整合 / 大 debug / 部署）。「Gate 和项目宁可慢，不要带着跑不通的代码往后走」。
2. **周复盘 / 阶段总结 → 周末做**：要回看整周 / 整阶段，和周末的大任务搭在一起。**周末时间不够时按此优先级保**：项目跑通 > debug 收尾 > 周复盘 > 知识库沉淀 > 下周预习；但沉淀留一条保命线——至少先在项目 `daily/notes` 记录本周最硬的坑或结论。只有用户使用「检查今天的学习」/明确授权同步，或普通 PASS 后确认，才写入 `D:\AI-Knowledge`。
3. **每日小结跟着任务走**：daily 文件里的「当天 / 总进度小结、问答点评」等，是「检查今天的学习」当天顺手回填的，**不攒到周末**。
4. **工作日遇到「下一个是 Gate」**：因为 Gate 要等周末，工作日就拉 **gate 无关的项**填上——B0/BE5 工程基础穿插补课 / 下一阶段的概念预习——别空等。
5. **关前工作日做「设计准备」**：周末要闯的 Gate，可先读资料、核对当前官方 API、规划结构和列函数；这时才创建该 Gate 的 TODO 骨架（**只设计不写实现**），让周末跑得顺。未来阶段不提前批量建骨架。
6. **强制顺序关卡**（`P0-Gate`、`L1-Gate`、`T3-Gate`、`A4-Gate`、`BE5-Gate`、`R6-Gate`、`G8-Gate`、`M9-Gate`、`FINAL-Gate`）没过，不进入后续同类阶段的**动手交付与该阶段 Gate**；`BE5-Gate` 在生产 RAG/可恢复 Agent 服务化前必须通过。其前的工作日按第 4 条填充（概念预习 / B0/BE5 穿插不受限）。
7. **算法 W4 起按内容块累计（3 新 + 1 旧错题，不可静默跳过）**：记录到 `tracker/algorithm-progress.md`；W4 没有旧题时做第 4 道新题。每个内容块预留 1–2 个独立算法时段；结转 `DEBT` 先占后续算法席位，旧债未清时不叠加下一块完整 `3+1`。同一内容块顺延超过 7 个自然日时再安排旧题复测；总量目标保留，时间线可延续到投递期。
8. **旧复习积压先消化、后开回收块**：到期间隔项 ≥4 或最老逾期 ≥7 天时，先连续两次练习优先使用原有最多 2 个旧复习席位；两次后仍超阈值，才在后续日计划内安排一个 20–30 分钟回收块，每天最多一个，并替换主块内容而非追加。🔴/🟡 活跃池没有伪造到期日，不按“逾期债务”累计。
9. **作品集分两档（别镀金玩具 Gate）**：PR2 等小 Gate 只做轻量卫生；全套打磨集中在领域 RAG 旗舰和从 A4→G8-00→G8→FINAL 持续演化的可控 Agent 旗舰，另保留结构化抽取小项目。不要把每个 Gate 都复制成新仓库。
10. **代码骨架即时创建**：未开始任务只在 tracker 里保留目标路径和通过标准；进入当天动手或 Gate 设计准备时再建 TODO 骨架。这样函数签名、SDK 字段和评估要求都基于当时真实资料，不维护一堆会过期的空文件。

## 三、顺延规则

- 不预设机动日、不预设降档。哪天加班 / 有事，**提前告诉我，那天顺延**，任务挪到后面。
- 没特别说的日子一律正常排任务、照常出题。

## 五、提醒

- 每天从第一次带读/动手开始就更新 `daily/YYYY-MM-DD.md`；不要等正式练习才记录。检查用 `ai-agent-learning-review` 判定并回填。
- 一个完整概念/阅读计划块以任务级 8–12 个总有效考察为上限和覆盖目标，常见分布为即时 4–7 + 正式 3–5；跨日短续学只补缺口，不按日期重置。编码、Gate 或项目块使用 5–8 个高质量检查点。旧复习目标默认 1、最多 2，包含在总量内；具体去重和题型由 `daily-practice-builder` 负责。
- W4 起每天只检查算法欠额是否需要排期，不代表每天都追加算法。内容块结束必须写 `算法配额 PASS/DEBT`，DEBT 顺延但不能静默消失。
- 周末除了 Gate / 项目，记得做一次**周复盘**，先回填项目内 `daily/notes`；只有使用「检查今天的学习」、用户明确授权，或普通 PASS 后得到确认时，才同步到 `D:\AI-Knowledge\07-Reviews\`。
- 有事耽误就主动说，**顺延是计划内的，不是失败**。
