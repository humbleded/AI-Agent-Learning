# 每周学习复盘与调整工作流

用户于 2026-09-07 授权每周定时复盘当前不足，并据此调整学习计划、Codex skill 和记忆。本文件规定执行方法；具体时间和启停状态由 Codex 已安排任务管理，修改时间使用 automation_update，不在文件中写调度规则。

当前采用用户选择的新方案：**每周完整检查各个方面，按变化决定阅读深度，按证据决定修改范围。** 下方步骤是现行规则；运行记录中的较早方案仅保留为历史。

## 每次怎么做

1. **每周覆盖完整范围，优先读取变化。** 先读最近接力、项目 `AGENTS.md`、`tracker/progress.md` 与当前 daily-plan。每次均检查教学方式、任务前后依赖、练习与算法、复习安排、资料及 GitHub 变化、skill 和记忆一致性；不以“当前学习没有卡住”或“本周没有作答”为由跳过这些方面。定位新增/修改的 daily、用户反馈、notes、代码、计划和规则，重点检查变化及已有风险；未变内容可复用有版本/证据位置的既有核验，不反复通读全部文件。变化涉及跨文件规则时，回读相关旧规则核对关系，即使对应文件本身未改。Git diff、文件时间和助手产物只用于定位变化，不直接证明用户学过或掌握。首次承接 [9/7 评审](learning-method-review-2026-09-07.md)，缺少核验依据的方面补齐最小必要读取；全部例行范围检查后仍无问题，保持计划原状。
2. **在全范围检查后，深入问题细节并复查旧调整。** 使用 `learning-coach` 审计模式，按发现的问题读取相关任务标准、资料、skill 和台账；本步控制深入程度，不限制第 1 步的每周检查范围；涉及跨日任务时补齐该任务全部关联证据，不能只看最近七天。区分前置缺失、讲解不足、安排不当、正常实现困难和规则冲突；一次 RETRY、尚未作答、跨周或没有学习活动，本身不支持改全局规则。反复出现的同类问题、明确用户反馈或可定位的依赖/规则错误，才支持相应调整。旧改法尚未遇到适用学习机会或独立证据不足时，保持待观察；发现明确反证或矛盾则及时修正，不必等下周。
3. **每周轻量核查收藏，相关变化再深入。** 分页核对 `humbleded` 的收藏清单及相关仓库的更新/提交线索，与最近检查记录比较；即使本周学习没有卡住，也完成这一层检查。新增收藏或更新不等于必须学习：涉及当前或后续任务的教学安排、资料失效、API/依赖变化或已知缺口时，才读对应正文/官方资料；不每周重读全部教材，也不批量克隆或因热度扩课。记录实际检查范围和必要版本，仓库元数据只能证明发现了更新线索，不能冒充正文已核验。无变化则沿用旧资料核验；网络或登录失败保留外部未核验事项，继续本地检查，本轮明确为部分完成。
4. **在问题所属层面小幅修正。** 单次讲解或题目有问题，先修当前安排；问题确实来自通用教学规则（如跨任务重复或可定位的规则错误）时才改对应 skill；路线依赖错误才调整任务顺序。每轮优先处理最影响当前学习的少数问题，不为改动数量扩大范围；同一改法尚待有效观察时不反复更换，明确错误除外。在授权范围内直接修改必要的计划、接力、资料、模板和 Codex 记忆，改 skill 前使用 `skill-creator`；替换旧矛盾，少加新规则。全局 Codex 记忆只改用户明确表达的跨项目稳定偏好。写前重新读现场、保护未提交与并发改动；不可安全合并的文件延后，不覆盖正在进行的学习接力。
5. **验证实际变化和未完成项。** 对改过的 skill 运行 `quick_validate.py`，检查受影响的依赖、字段、链接、跨日覆盖及预览/练习/阶段检查/完整验收分流，并做适用的 `git diff --check`。此前尚未完成的适用验证须在条件恢复后补做；已经完成且目标内容未变化的验证不重复运行。实质性路线/验收/多文件规则变更安排独立代理先读依据形成结论，再读主审意见；修复分歧后复查。用场景推演验证规则，不制造作答、不跑无关课程测试；此代理审计不替代正式学习/岗位的另一工具复核。
6. **记录覆盖、事实和效果，不追逐每周评分。** 简记本轮覆盖范围及新增/复用的依据、检查日期与证据截止位置、问题依据、实际改动或合理保持原状、验证和未完成事项；不把逐项核查扩成冗长周报。对实质调整加一句“原问题 → 改法 → 下一次在哪类实际学习动作中观察 → 当前证据/结论”；结论可为未到观察机会、证据不足、有改善、需修正。没有再次出现问题不自动证明有效，不为验证方法额外给用户出题。定时任务不强制打分，也不把达到 90 分作为结束条件；五维评分留给用户要求的完整方案评审，历史 93 分只代表当时方案，不作为新一周效果分。全范围检查无新问题时只记最小检查结果，不改规则或追加重复总结。

检查位置至少标明已读任务/Session 或证据 ID，必要时带相关提交或文件内容版本。运行重试时复用同一条记录，同一批证据不重复修改或追加相同总结；本工作流产生的记录和规则修改本身不算新的用户学习证据。同日出现了新作答或新实现时仍读取相应增量，不能只因日期相同跳过。

运行结果区分“完成、部分完成、受阻”。只有实际读过并完成适用验证的范围才能推进检查位置；外部未核验资料、未解决分歧及并发延后的文件保留各自原起点和待办，下一次先接续，不能把本地部分完成写成全部成功。

- 本工作流不替代正式任务验收、W6/W12/W16/W19 岗位审计、知识库维护或算法 Session。算法与弱点台账可以检查安排是否冲突，但只有真实复测与正式验收流程才能修改其事实状态/排期。
- 没有新授权时不提交/推送 Git、不写 `D:\AI-Knowledge`、不部署、不购买服务；需要用户决定的新增目标、费用或无法核实的关键偏好，先把具体可审核方案完成，其余已授权独立工作继续。
- 本次修改是否有依据、是否最小、是否通过检查，与后续学习效果是否已验证分开记录。无新增且无可执行事项保持安静；只有有意义的改动、新的或发生变化的失败/阻断、需要用户决定时说明。相同且无需用户处理的已知外部失败保留记录，不反复通知。
